# Maintainer tools

## `generate-entitlement-db.mjs`

Generates `src/RockBandSpotify/wwwroot/data/entitlements.json`, the **static**
entitlement database the app ships with.

```bash
node tools/generate-entitlement-db.mjs entitlements-raw.json [more-dumps.json ...]
```

Input is one or more raw PSN entitlement dumps (see `tools/psn-rockband.ps1`,
which writes `entitlements-raw.json`). The output file is committed to the repo
and only ever regenerated by running this script — the live app never writes to
it, and nothing is collected from users.

### Why three tables

PSN's Rock Band content codes are not one format. They fall into three kinds,
and only one of them can be derived from the song catalogue alone:

| Kind | Example | How a song is identified |
|---|---|---|
| Title-bearing | `RBALLIWANCCF01FE` | Truncated title + a release-order counter. Resolved at runtime against `catalogue.json`; this file supplies only the `calibration` curve used to break ties between songs sharing a truncated title. |
| Pack | `RB1EXPORTCCF0099` | One entitlement granting a whole tracklist. Expanded through the catalogue's `source` field via `PACK_SOURCES` in the script. |
| Opaque | `PROCKBANDX000012` | A bare product number with no title in it. **Nothing can derive these** — they need a hand-confirmed mapping in `opaque`. |

### The `unidentified` list

Opaque codes seen in a dump that nobody has mapped to a song yet. They are
recorded so the gap is visible rather than silently dropped. Filling one in
means adding a `"CODE": songId` entry to `opaque` — which requires knowing, by
some means outside the code itself, which song that product actually is.

### Adding pack contents

`PACK_SOURCES` maps a pack's code prefix to the catalogue `source` value(s) it
grants. A pack's contents are a fact about what Harmonix sold, so this is
hand-maintained; add an entry when a dump turns up a pack code that isn't
covered.

## `psn-rockband.ps1` / `psn-names.ps1`

Local PowerShell scripts for pulling your own entitlements (`psn-rockband.ps1`)
so the token never leaves your machine.

`psn-names.ps1` tries to resolve names from the PSN Store product pages. It is
kept for reference only — Store name resolution proved unreliable (the store
does not consistently server-render titles), which is why the code-based
approach above exists.
